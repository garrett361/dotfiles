# RL system invariants

Desired invariants to check designs and PRs against. Status: enforced (holds in `main` today), gap (targeted but violated somewhere), desired (not yet built). Keep each item to one line and the file under 100 lines. The pipeline items come from the RL pipeline design doc (PR #3963), which also lists the detailed gaps.

## Pipeline

1. Every opened train group ends in exactly one terminal state once all its attempts are accounted for. (gap: wind-down and self-cancelled episodes skip accounting)
2. No trained token was generated by a policy more than `max_off_policy_steps` versions behind the policy it trains. (enforced)
3. Batch N ships only once inference serves at least `v{N-2}`. (enforced)
4. A new episode starts only while in-flight episodes are below the cap, and the cap stays within its bounds. (enforced)
5. No new episode starts while a weight update is in progress; running episodes continue across it. (enforced)
6. Every trainer data-parallel rank receives the same number of micro-batches per step, with matching modality at each index. (enforced)
7. The orchestrator stays alive through the trainer's final weight broadcast. (gap: the final wait can time out)
8. Every wait on another component is bounded or fails when that component dies. (gap: several unbounded waits)
9. Emitting a result never blocks; back-pressure acts only on starting new work. (enforced)
10. Each eval result measures one policy version. (gap)

## Resilience

11. A single-component failure restarts only that component. (desired)
12. Completed rollouts survive any single-component restart. (desired)
13. A rollout trains at most once per policy lineage. (desired)
14. Rollout data is deleted only after a committed trainer checkpoint covers it, or after it is dropped. (desired)
15. Writes and pulls from an older `(epoch, version)` lineage are rejected. (desired)
16. The orchestrator holds no per-token data; it decides from metadata only. (desired)
17. Every component exposes health, readiness and control endpoints. (desired)

## Known gaps beyond PR #3963's list

- Sending a batch to the trainer has no timeout, so a stalled trainer freezes the orchestrator's main loop.
- Running env-server episodes have no liveness check.
- Scored but unshipped samples are lost on resume, and the curriculum has already moved past their tasks.
- The trace index takes an episode's start time from its first-completed trace, which misreports multi-trace episodes.
